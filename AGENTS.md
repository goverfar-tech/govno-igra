# AGENTS.md — правила для ИИ-агентов этого репозитория

> Прочитай этот файл ПОЛНОСТЬЮ в начале каждой сессии, до любой работы.
> Затем прочитай **MEMORY.md** — там живая память проекта, статусы этапов
> и целевая мета (§9, майонезное ведро, хоррор-мультяшный тон).

## 1. Идентичность проекта
- Одиночная 3D FPS survival-игра, Unity 6 LTS (6000.0.32f1), C#.
- Активный проект: `unity/`. Остальное в корне — архив Godot-эталона
  (не править, не удалять до конца миграции; MEMORY.md §2, §10).
- Тон: мрачно-мультяшно, spooky-cute (Don't Starve / Tim Burton).
  Мир серьёзен, ситуация абсурдна — юмор в деталях, не в кривлянье.

## 2. Железные правила среды
- Проект открывается ТОЛЬКО через junction `E:\survival-unity`
  (ASCII-путь; кириллица в пути ломает glTFast).
- Сцена `Main.unity` пересобирается ТОЛЬКО скриптом
  `Survival → Setup Main Scene` (SetupMainScene.cs). Ручные правки сцены
  будут стёрты следующим запуском Setup — мир менять кодом в
  SetupMainScene.cs.
- Предметы — ScriptableObject в `Assets/Resources/Items` (грузятся
  рантаймом по id, нужно SaveSystem). Рецепты — `Assets/Resources/Recipes`.
- GLB-модели Kenney: пакет glTFast; текстура обязана лежать в
  `Assets/Models/Textures/colormap.png`.
- Числа баланса брать из Godot-эталона (`scripts/`, `resources/`
  в корне), не выдумывать (MEMORY.md §10).

## 3. Владение файлами (изоляция потоков)
Проект ведётся параллельными чатами. Прежде чем править чужой файл —
остановись и договорись через автора.
- Главный поток (мир/механики): `SetupMainScene.cs`, `Scripts/World/`,
  `Scripts/Interaction/`, `Scripts/Player/`, `Scripts/Core/`, MEMORY.md.
- Звук: `Scripts/Audio/`, `Assets/Audio/`.
- UI: `Scripts/UI/`, `Assets/Resources/Icons/`, `Assets/Resources/Recipes/`,
  и единственный файл `Scripts/Items/RecipeData.cs`.
- `GameEvents.cs` — append-only для всех: новые события дописывать
  в конец класса, существующие не трогать.
- В ассетах Unity `.meta` файлы коммитим вместе с ассетами.

## 4. Как работать над задачей
Когда автор даёт новую задачу, агент:
1. Перечитывает MEMORY.md (статусы могли смениться другим потоком).
2. Разбивает задачу на подзадачи. Если задача нетривиальна — сначала
   ОДИН или НЕСКОЛЬКО исследовательских проходов (суб-агент Explore /
   grep по эталону и текущему коду), потом реализация по фактам,
   а не по памяти. Большие реализации можно делегировать суб-агентам
   с чётким списком файлов, которые им принадлежат.
3. Перед крупной системой — краткая предлагаемая архитектура автору
   (правило из MEMORY.md §4).
4. Коммит после каждой завершённой системы; игра должна открываться
   после каждого коммита (компилируемость обязательна).
5. `git push origin master`; при `rejected` → `git pull --rebase` → push.
6. Обновить статус в MEMORY.md (главный поток) — или попросить его,
   если ты параллельный поток.

## 5. Запреты
- Не добавлять платформенные модули Unity (лимит диска 60–70 ГБ,
  реально ~20). Только Windows Build Support.
- Не качать внешние платные ассеты; Kenney/Quaternius — дозволено.
- Не менять тон без отметки в §9 (последнее уточнение: мрачно-мультяшно,
  2026-09-30).
- Docker не нужен. Мультиплеер — только отдельным решением (§9.1).
